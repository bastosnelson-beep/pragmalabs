# /veille-ia — Pipeline de veille IA

## Objectif

Produire chaque jour un **digest dense (~20 min de lecture)** de l'actualité IA dans `3 GARDEN/Veille IA Digests/YYYY-MM-DD.md`, avec :
- Seulement le **nouveau** depuis le dernier run (différentiel)
- **Anti-redite** : jamais un sujet déjà traité dans un digest précédent
- Insights, connexions, réflexions — pas une liste plate
- Sources brutes archivées dans `3 GARDEN/À traiter/Veille IA/YYYY-MM-DD/`

## Scope & chemins (STRICT)

Tout se passe **dans `3 GARDEN/`** — jamais dans Perspectives ou ailleurs.

```
/Users/eliottmeunier/Documents/WORKSPACE/DigitalGarden/3 GARDEN/
├── À traiter/Veille IA/
│   ├── .state.json                   # état (last_run, hashes, topics vus)
│   └── YYYY-MM-DD/                   # sources brutes du run
│       ├── youtube/<channel>/<id>.md
│       ├── substack/<source>/<slug>.md
│       ├── labs/<lab>/<slug>.md
│       ├── twitter/<user>/<thread-id>.md
│       └── benchmarks/<source>-<date>.md
└── Veille IA Digests/
    └── YYYY-MM-DD.md                 # digest à lire (output principal)
```

## Flow d'exécution

### Étape 1 — Charger l'état

Lire `3 GARDEN/À traiter/Veille IA/.state.json`. Si absent, initialiser :
```json
{
  "last_run": null,
  "seen_urls": [],
  "seen_video_ids": [],
  "covered_topics": []
}
```

`covered_topics` = **clé pour l'anti-redite**. Liste de concepts/news déjà traités dans des digests précédents, format : `{"slug": "claude-opus-4-6-launch", "date": "2026-04-15", "summary_1line": "..."}`.

`last_run` définit le cutoff : ne scrape que ce qui est postérieur.

### Étape 2 — Scrape par catégorie (parallèle)

**YouTube** — pour chaque chaîne :
```bash
yt-dlp --flat-playlist --dateafter "$LAST_RUN_YYYYMMDD" \
  --print "%(id)s|%(title)s|%(upload_date)s" \
  "https://www.youtube.com/@<channel>/videos"
```
Puis pour chaque nouvelle vidéo : `yt-dlp --skip-download --write-auto-subs --sub-langs en --sub-format vtt`, convertir en markdown (voir logique dans `/tmp/nate-scrape/vtt_to_md.py` — pattern : dédupe lignes, clean tags `<c>`, paragraphes tous les 6 lignes).

**Substacks + Blogs labs** — Firecrawl :
```
mcp__firecrawl-mcp__firecrawl_scrape(url, formats=["markdown"], onlyMainContent=true)
```
Pour les pages archive : extraire les liens d'articles postérieurs à `last_run`, puis scrape chacun.

**Twitter** — via Nitter :
```
mcp__firecrawl-mcp__firecrawl_scrape("https://nitter.net/<user>", formats=["markdown"])
```
Extraire tweets/threads postérieurs à last_run. Ignorer retweets.

**Benchmarks** — snapshot markdown d'Artificial Analysis + LMArena + HuggingFace trending. Comparer avec le snapshot précédent pour identifier nouveaux modèles / changements de ranking.

### Étape 3 — Dédupe & filtrage

- Hash chaque URL → rejeter si dans `seen_urls`
- Pour chaque item restant : générer un **topic_slug** (ex: `claude-opus-4-6-launch`) via LLM
- Rejeter si `topic_slug` matche approximativement un `covered_topics` existant (similarité sémantique > 0.8)

### Étape 4 — Archive brute

Écrire chaque source scrapée dans `3 GARDEN/À traiter/Veille IA/YYYY-MM-DD/<category>/<slug>.md` avec frontmatter :
```yaml
---
type: veille-source
category: youtube|substack|labs|twitter|benchmarks
source: "<nom source>"
url: "<url originale>"
scraped_at: "YYYY-MM-DD HH:MM"
topic_slug: "<slug>"
---
```

### Étape 5 — Génération du digest (cœur du skill)

Créer `3 GARDEN/Veille IA Digests/YYYY-MM-DD.md`.

**Contraintes rédactionnelles strictes :**
1. **~20 min de lecture** = 4000-6000 mots denses
2. **Anti-redite absolue** : si un topic est dans `covered_topics`, ne pas le re-couvrir, même sous un angle voisin. Si c'est une évolution réelle (ex: GPT-5.4 → 5.5), introduire par "Suite de [topic précédent du DATE] : ce qui est nouveau est..."
3. **Zéro remplissage** : pas de "il est important de noter que", pas d'intro généraliste sur l'IA. Direct au signal.
4. **Insights perso**, pas listing : "X a sorti Y" → non. "X a sorti Y, ce qui casse l'hypothèse Z que tout le monde avait, parce que..." → oui.
5. **Connexions** : cross-référencer avec notes existantes dans `3 GARDEN/Notes/` via QMD si disponible. Format : `→ lien avec [[Note X]]`.

**Structure du digest :**

```markdown
---
type: veille-digest
date: YYYY-MM-DD
period_covered: "YYYY-MM-DD → YYYY-MM-DD"
sources_count: N
items_new: N
---

# Veille IA — <Date en FR>

## ⚡ TL;DR — Les 5 signaux qui comptent cette semaine/ce jour

1. **[Signal majeur]** — 1-2 phrases avec l'insight, pas la news
2. ...

---

## 🔬 Modèles & Labs

Les releases, papers, shifts stratégiques. Prioriser l'analyse sur la news.

### [Titre signal 1]
Exposition contexte (2-3 phrases). Pourquoi c'est non-obvious. Ce que ça casse / révèle.
**Source :** [lien]
**Insight :** ce que ça implique pour ta pensée / ton positionnement
**→ Connexion :** [[Note X]] / [[MOC IA]]

### [Titre signal 2]
...

---

## 🧠 Voix (ce que disent les têtes pensantes)

Synthèse fine de ce que Karpathy, Mollick, Amodei... ont dit de neuf. Pas "X a tweeté Y", plutôt "X et Y convergent sur Z, ce qui contredit W".

### Pattern émergent 1
...

---

## 📚 Deep-dives (articles longs)

Pour chaque Substack/article long majeur : **synthèse de 300-500 mots** qui rend la lecture de l'original optionnelle, avec la thèse, les 3 meilleurs arguments, et les points faibles/angles morts selon toi.

### [Titre article] — [Auteur, source]
[Thèse en 1 phrase]
[Les 3 arguments structurants, développés]
[Angles morts / ce qui manque]
[Lien vers source]

---

## 🛠️ Benchmarks & nouveaux modèles

Snapshot changements depuis dernier digest : nouveaux entrants dans les leaderboards, modèles open-source à surveiller. Format tableau compact + 2-3 phrases d'analyse par item qui bouge.

---

## 🎯 Angles potentiels pour ton contenu

3-5 angles éditoriaux qui émergent de cette veille, scorés rapidement (résonance / originalité / timing). Ces angles peuvent ensuite alimenter `3 GARDEN/Angles/` via une commande future.

1. **[Angle]** — pourquoi maintenant, pourquoi toi, angle inédit
2. ...

---

## 🔗 Connexions avec ton Garden

Notes du `3 GARDEN/Notes/` qui résonnent avec les signaux de ce digest. Suggestions de nouvelles notes permanentes à atomiser.

---

## 📌 Topics couverts (pour anti-redite — ne pas éditer)

- topic-slug-1
- topic-slug-2
```

### Étape 6 — Update state

Après génération réussie :
- `last_run` = now
- Ajouter tous les `seen_urls`, `seen_video_ids` nouveaux
- Ajouter tous les `topic_slug` couverts dans le digest à `covered_topics` (avec date + résumé 1-ligne)
- Écrire `.state.json`

## Règles de qualité du digest

**À faire :**
- Citer les sources avec liens cliquables
- Mettre en gras les **noms propres** (Karpathy, Amodei, Lütke...) et les **chiffres clés**
- Créer des wikilinks `[[Concept]]` quand un concept mérite une note permanente (signal pour plus tard)
- Synthétiser plusieurs sources convergentes en un seul signal ("3 labs ont convergé sur...")
- Donner un avis tranché quand pertinent ("ça ressemble à une erreur stratégique parce que...")

**À éviter :**
- Pas de listing plat "X a sorti Y" sans analyse
- Pas de redite d'un topic déjà traité (check `covered_topics`)
- Pas de généralités sur l'IA ("l'IA transforme tout")
- Pas de "selon moi" — formuler direct avec autorité
- Pas d'emojis sauf les 6 de la structure de base du digest

## Exécution

Quand l'utilisateur lance `/veille-ia` :

1. **Annoncer** le scope qui va être scrapé + date de dernier run
2. **Demander confirmation** avant de lancer (règle Digital Garden : toujours confirmer)
3. Exécuter le pipeline en parallélisant par catégorie (xargs -P 6 pour YouTube, Firecrawl en batch)
4. À la fin, afficher :
   - Chemin du digest créé
   - Nombre d'items nouveaux par catégorie
   - Topics ajoutés à `covered_topics`
   - Sources skippées (avec raison)

## Recovery & edge cases

- Si Firecrawl timeout sur une source → skip + noter dans digest section "Sources indisponibles"
- Si Nitter entièrement down → skip Twitter, noter
- Si yt-dlp échoue sur une vidéo (sous-titres désactivés) → skip + noter
- Si aucun nouveau contenu depuis last_run → générer un digest minimaliste "Rien de majeur depuis [date]. Prochain run recommandé dans X jours."
- Si > 50 items nouveaux (premier run ou après longue pause) : grouper par thème, ne pas produire un digest de 100 pages — cap à ~6000 mots en priorisant par signal.
